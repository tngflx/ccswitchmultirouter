# Responses Request Contract

The reviewed fixture `openai-responses.v1.json` is embedded in the existing
Request Health checker. Checks run on the final outgoing Responses create body
after provider transformations and overrides, including Lite fallback.
Enable Request Health in CC Switch to see redacted findings in its existing
panel and router logs. Retry attempts replace the same trace's diagnostic.

This is a conservative checker, not the entire OpenAI schema. It covers known
top-level types, selected nested types, conversation/previous-response conflicts,
compaction-trigger placement, additional-tool roles, tool choices, and selected
tool-call shapes. Existing Request Health owns call/output relationships.
The hosted-search replay invariant reuses the existing repair/check implementation.
Unknown extensions are informational and are not removed or blocked.
Live traffic remains diagnostic-only; synthetic protocol probes reject known
local contract errors before dispatch.

## Documentation Drift

```powershell
pnpm contract:check
pnpm contract:test
pnpm contract:drift
```

The first two commands are offline CI gates. The third fetches only the public
official Responses create reference and compares typed declarations and selected
invariant evidence. Production requests never fetch documentation. A weekly,
read-only GitHub workflow and manual dispatch run the drift check once this code
is on the default branch. A failed workflow is a maintenance signal, not an
automatic runtime update.

Review changed official declarations and runtime rules before explicitly running:

```powershell
pnpm contract:refresh
```

Refresh updates reference signatures, item/tool kinds, digest, and verification
date. It does not invent new field-type rules or rewrite runtime invariants.
Evidence changes require manual review. Review the diff, update conservative
rules and regression tests as needed, then run contract and Rust tests.

## Selected-Provider Canary

Start the existing local proxy on port 15721 with the desired route selected:

```powershell
pnpm canary:test
pnpm canary:replay --model gpt-6.1-sol-sublyx
```

This opt-in suite makes up to three paid provider requests: one actual hosted
search, standard compaction replay, and Lite compaction replay. It replays only
history generated by that synthetic search and intentionally omits search-tool
declarations to exercise the shared repair. It stops on the first failure.
It never opens an original conversation or reads stored credentials; the local
proxy resolves credentials using the existing PROXY_MANAGED route.

Success requires HTTP 200, explicit completed terminal status, no terminal error,
actual search output, and actual compaction output in both replay stages.
The suite uses a 240-second deadline, at most 30-second blocking reads,
2 MiB capture and 4,096-event limits. It requests an output limit, but provider
normalization may remove unsupported limits; this is not a guarantee of
provider-side billing caps. The canary deliberately avoids optional
provider-specific limits that are unrelated to the replay invariant. Output
contains status, counts, and fixed failure categories, never prompts, history,
search results, or raw upstream errors.

Passing does not certify every model, extension, transport, replay path, or
private Sublyx/ChatGPT backend contract. It does not verify how proprietary Codex
UI renders errors or that an original stuck conversation now completes.
