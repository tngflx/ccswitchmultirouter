## English

### Release focus

This release publishes the integration record that was missing from the previous GitHub release and completes the model-catalog, MultiRouter, and release-toolchain work accumulated in this fork. It explains both what changed and how upstream work was adapted without replacing CCSwitchMulti's fork-specific routing, OAuth, traffic-policy, Sub-Agent V2, and four-locale UI contracts.

### Model catalogs and free-model workflow

- **Authoritative synchronization:** a complete provider `/models` response now removes remote-bound catalog rows that the provider no longer advertises. Manual rows without an explicit upstream binding remain intact.
- **Partial multi-key safety:** the fallback key and every enabled grouped key are fetched and deduplicated. If any credential fails, successful results are merged but unmatched rows are retained so an account-specific model is never deleted from an incomplete union.
- **Consistent entry points:** the provider form, four-step MultiRouter wizard, official OAuth sync, and route workspace now use the same complete-versus-partial reconciliation contract.
- **Temporary catalog filtering:** typing `free` or another query temporarily reuses the catalog list area for matches across model id, upstream id, and display name. Include Filtered or Exclude Filtered applies exactly those visible matches, clears the temporary query, and opens the corresponding persisted Included or Excluded view.
- **Downstream cleanup:** removed models are also removed from fixed route selections, custom ordering, projection candidates, and spawn-agent priority lists. Retained aliases, exclusions, capabilities, and user ordering remain stable.

### MultiRouter and provider UI

- The MultiRouter wizard now fetches every enabled grouped credential instead of only the fallback key and reports incomplete credential fetches without destructive pruning.
- All four wizard stages were re-audited: model-source selection, automatic catalog/protocol preparation, model selection and route preview, and explicit enable/verification.
- The wizard now uses a mobile two-by-two step grid and a full-width content column, preventing the desktop sidebar from crushing content on narrow windows.
- English no longer falls back to Chinese in the main MultiRouter button, source-choice dialog, preset selector, provider guidance, advanced configuration, or input placeholders. New keys are present in English, Simplified Chinese, Traditional Chinese, and Japanese.
- Provider labels remain compact while stable provider ids and exact upstream model ids stay available for diagnostics and routing.

### Codex routing, probing, and resilience already integrated in this release line

- Schema-v2 MultiRouter keeps endpoint, credentials, protocol, context, and capabilities owned by target providers; routes store only selection, aliases, prefixes, and auth policy.
- Deep protocol verification runs baseline JSON, SSE, reasoning, forced-tool, and tool-continuation stages for both Responses and Chat, with redacted per-model progress and outage-aware classification.
- Verified provider protocol profiles are synchronized into dependent routes and inherited at runtime without copying credentials into route configuration.
- Codex Desktop model-picker projection, Guardian/CDP reinjection, model/provider label styles, ordering, and spawn-agent candidate projection remain integrated with the provider-owned catalog.
- Tiered recovery separates safe pre-semantic reconnects from bounded Codex Desktop `continue` submissions.
- Grouped API-key routing, provider reasoning-content modes, Codex traffic policy, official-auth preservation, hosted-tool diagnostics, and Sub-Agent V2 profiles remain fork-owned and intact.

### Deliberately not merged wholesale

- The full upstream OAuth/JWT rewrite remains deferred until its account-store, command, and provider conflicts can be ported hunk by hunk without losing managed OAuth isolation.
- Pi usage deduplication was not applicable because this fork has no `session_usage_pi.rs` path.
- Recent BigStrongSun probe/reasoning/profile changes were not duplicated where equivalent fork adaptations were already present.

### Other fixes included since the prior documented release

- OpenCode Go subscription usage supports rolling, weekly, and monthly windows with defensive response parsing.
- Otty is available as a tab-aware terminal target.
- Restores no longer erase unmanaged prompt files when a synchronized database contains no enabled prompt.
- The updater can report exact commits behind the configured fork repository.
- Existing catalog metadata can be refreshed without overwriting aliases, exclusions, reasoning overrides, or custom ordering.
- Codex provider writes can explicitly skip the hidden automatic deep probe when the wizard already owns the probe stage.

### Release and updater infrastructure

- The updater endpoint, compare links, product links, and tray links now point to `tngflx/ccswitchmultirouter`.
- The updater public key is rotated to the key used by this repository's release environment; private signing-key files are ignored by Git.
- Node is pinned to **22.23.2** across local development and every CI/release workflow. pnpm is pinned to **11.24.0**, the latest pnpm v11, and package engines reject unsupported Node/pnpm major versions.
- GitHub release generation now embeds the English, Chinese, and Japanese release-note files instead of silently falling back to a one-line placeholder.

### Upgrade notes

- A complete model sync is now authoritative for remote-bound rows. Keep intentionally manual models without an explicit upstream binding.
- When one grouped credential fails, the UI reports a partial sync and intentionally leaves unmatched rows unchanged. Retry after restoring that credential to obtain an authoritative prune.
- Restart Codex Desktop/app-server after changing projected model order, model-picker visibility, MultiRouter activation, or Sub-Agent protocol.
