## Findings and fixes

- The frontend model picker uses canonical selectable reasoning efforts, not a
  hard-coded Max ceiling. Provider-native effort editing and Codex Ultra
  orchestration are different contracts; Sub-Agent v1 intentionally excludes Ultra.
- Updated Desktop numeric initialized-cache discovery is bounded and same-origin.
  Cache projection alone does not establish final native menu visibility. Current
  account/local native visibility preferences have **not** been established live.
- Additional regressions exposed stale scope/client ownership, orphaned exported
  scope promotion, semantic fallback imports authorized by unused lazy dependency
  strings, and post-await continuation authorization races. Current-owner proof
  must remain distinct from patchable inventory and restoration state.
- Continuation now requires an exact request model and independently validated
  thread/turn identity. Missing or conflicting model metadata cannot authorize a
  mutation. Backend and renderer tests explicitly exercise the same contract.
- Upstream Provider-backend routing is resolved before external API protocol
  selection. Legacy, schema-v2 live-target/canonical-empty, and plain/disabled
  provider regression cases cover the adaptation.
- Upstream model metadata and official-model inclusion controls were
  assimilated without dropping the fork's rich inventory or canonical catalog
  authority. Final commit matrix and verification results are recorded below.

- The shared Gemini/OpenClaw fetch hook still accepted results for an obsolete
  endpoint/key and could let an older request clear a newer loading state. It
  now uses opaque commitm,ted identity, sequence, mounted, and state-updater guards;
  stale results are hidden immediately, including A -> B -> A identity changes.
  Current-identity refresh failures retain usable results. Raw errors are no
  longer written to the console, preserving existing safe UX classification.
- Paginated model discovery could resend original authentication headers to a
  redirected origin. A discovery-specific same-origin redirect policy now
  protects standard and custom auth headers on the first request and later
  pages, reusing the existing configured-proxy transport builder. Global/inference
  redirect behavior is unchanged; legitimate same-origin paging remains valid.
- Official Zhipu documentation enrichment now requires an exact parsed HTTP(S)
  host, not a matching hostname hidden in another host, path, userinfo, or query.
  Inactive TOML provider blocks and case-only pagination duplicates can no longer
  supply vendor capabilities or falsely certify complete discovery.
- CDP renderer target selection now fails closed on spoofed or unsafe targets.
  It requires a loopback `ws://` debugger URL on the exact candidate port, with
  no userinfo, query, or fragment; URL-only `app://codex` markers no longer
  identify Codex, while the packaged `app://-/index.html` fallback still requires
  a verified Codex Desktop listener.

### Native Max visibility root cause (follow-up, November 6, 2026)

The post-restart evidence separated the remaining native picker problem from the
catalog/query work that was already passing. CCSwitch was successfully projecting
33 models (18 reasoning, 15 Max, 8 Ultra), but the installed Codex Desktop
`26.1029.7803.0` renderer still filtered the final menu through its native
enabled-effort atom (`Q3tq.pN`). The installed bootstrap default contains
`low`, `medium`, `high`, `xhigh`, `ultra`, and `persistent`; it does **not** contain
`max`. The model-query module applies that Set after the projected catalog, so
Max disappears even when the catalog and query cache contain Max rows. The
separate `showUltraInModelPickerSlider` schema flag is not a live consumer; Ultra
continues to use Codex's independent `includeUltraReasoningEffort`/Statsig gate.

The compatibility layer now reconciles this final native projection only for a
managed catalog that actually contains Max-capable rows. It uses the exact
current React-owned scope and discovered `Q3tq.pN` atom, clones the native Set,
adds `max`, and installs no persisted/native preference change. The original Set
and scope/atom ownership are retained for deterministic restoration on catalog
release, renderer reinjection, scope replacement, or any uncertain ownership
state. This is intentionally narrower than enabling Max globally and does not
force Ultra. The regression harness covers the missing-Max RED case, Max-capable
managed catalog GREEN case, and restoration after release/reinjection.
